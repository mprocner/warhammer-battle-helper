Approach 2 — Modal · Token Editing Mockup

Warhammer Battle Helper · Static HTML
Concept: A small edit button (⚙) appears on the selected token. Clicking it opens a full centered modal over a dimmed backdrop. The modal contains complete HP management, a comprehensive 5×2 conditions grid with per-condition level controls, and a full stats editor. The grid is visible but dimmed behind the modal — active state badges and the HP bar remain readable at z-index above the overlay.

Trade-off: Maximum information density and edit clarity — ideal for deep character setup between encounters. Blocks the map view, breaks the "in-the-moment" combat feel. Requires a deliberate open/close cycle.
Normal gameplay — HP bar & active states always visible (no modal open)

Edit icon (⚙): Appears in the bottom-right corner of the selected token's circle. Clicking it opens the modal. Clicking anywhere on the backdrop (overlay) or pressing Escape closes the modal without saving, or auto-save on change.
Tokens visible behind overlay: The selected token's HP bar and active state badges stay at a higher z-index than the backdrop so the player can see what they're editing. Other tokens are dimmed at opacity 0.4.
Conditions grid — full control: Each condition card shows icon + name + level stepper (+/−). Inactive = greyscale. Active = golden glow. Clicking an inactive state activates it at level 1. Level can go to max (defined per state by game system).
HP controls: Dual-mode — large +/− buttons for quick combat adjustments, plus direct number inputs for setting exact values (e.g., after long rest). Bar animates fill on change.
Stats section: Full editable stats with +/− per field. In React: connected to the character's live state in GameSession; changes broadcast via WebSocket to all players.
Scalability: Modal can scroll vertically if the game system defines many conditions or stats. This makes Approach 2 the best fit for a "full editor" — accessible from the other two approaches via an expand/detail button.
