# BUG-192 — Długa nazwa atrybutu w logu nie jest obcinana ani zawijana

**Status:** zaprojektowane, gotowe do planu implementacji
**Zgłoszone:** 2026-09-08

## Objaw

Customowa karta postaci. Gracz rzuca na atrybut o długiej nazwie (np. „Odporność na działanie
magii chaosu"). Wpis w logu czatu pokazuje tę nazwę bez zawijania i bez skrócenia — tekst wylewa
się poza panel logu.

Oczekiwane: nazwa skrócona z `…` na końcu, a po najechaniu kursorem tooltip z pełną nazwą.

## Przyczyna

`systems/custom/rolls/CustomRoll.jsx:84` renderuje etykietę jako element **inline**:

```jsx
{skillLabel && <strong className="log-list-item__character-name">{skillLabel}</strong>}
```

Klasa `.log-list-item__character-name` (`components/LogWindow.css:154`) ma już wszystkie trzy
własności potrzebne do ellipsis:

```css
min-width: 0;
overflow: hidden;
text-overflow: ellipsis;
white-space: nowrap;
```

Ale `overflow` i `text-overflow` **nie działają na non-replaced elementach inline** (CSS Overflow
§2: `overflow` na inline boxach nie ma efektu). Zostaje więc tylko `white-space: nowrap` — czyli
sam zakaz zawijania, bez obiecanego skrócenia. Efekt: przepełnienie kontenera.

Ta sama klasa **w nagłówku** wpisu (`__header`) działa poprawnie, bo tam element jest flex-itemem —
flex blokifikuje dzieci, więc `overflow` ma na czym się oprzeć. Stąd rozbieżność: ta sama klasa,
dwa różne zachowania zależnie od kontekstu rodzica.

w **10 komponentach rzutów w 4 systemach** — nie tylko w custom. Fix jest wspólny, żeby bug nie
wrócił przy dodaniu kolejnego systemu gry.

## Rozwiązanie

### 1. Fix CSS — jedno miejsce

`.log-list-item__character-name` (`components/LogWindow.css:154`) dostaje kontekst blokowy:

```css
display: inline-block;
max-width: 100%;
vertical-align: bottom;
```

To samo naprawia ellipsis we wszystkich 23 miejscach — klasa miała już `nowrap`, `overflow` i
`text-overflow`, brakowało jej wyłącznie kontekstu, w którym te własności obowiązują. W nagłówku
`inline-block` jest bez efektu (flex i tak blokifikuje dzieci), więc nagłówek nie zmienia wyglądu.

`vertical-align: bottom` jest korektą, nie kosmetyką — patrz Ryzyka.

### 2. Nowy komponent — `src/components/log/TruncatedLabel.jsx`

```jsx
// props: text, className, as ('span' | 'strong', domyślnie 'span')
```

Samowystarczalny: trzyma własny `usePortalTooltip` i renderuje swój `tooltipNode`. Zero plumbingu
propsów przez 13 call-sites — dziś hook ma tylko `CustomRoll.jsx`, pozostałych 12 plików nie
miałoby czego przekazać. Jeden `useState` na etykietę jest kosztem bez znaczenia; alternatywa
(kontekst tooltipa na poziomie `LogWindow`) dokłada globalny provider dla jednej funkcji.

Tooltip odpala się **tylko przy realnym obcięciu**:

```jsx
onMouseEnter={e => {
  const el = e.currentTarget;
  if (el.scrollWidth > el.clientWidth) showTooltip(text, el);
}}
```

Dokładnie wzorzec z `systems/custom/CustomSheetBody.jsx:445`. Powód warunku: ellipsis jest
sygnałem „jest więcej do przeczytania", więc nazwa która się mieści nie potrzebuje hinta na hover.
`scrollWidth` to szerokość nieobciętej treści, `clientWidth` widocznego boksa — różnią się dokładnie
wtedy, gdy `overflow: hidden` coś uciął.

Ikona broni idzie do `text` całościowo (`⚔ ${weaponName}`), więc tooltip pokaże „⚔ Halabarda
dwuręczna". Osobny prop `prefix` wyłączony z tooltipa to komplikacja bez zysku.

`CustomRoll.jsx` zachowuje swój `usePortalTooltip` — używa go do kostek puli (`:105`), po migracji
nie jest to martwy kod.

### 3. Layout przy nazwie dłuższej niż linia

Nazwa może zająć do 100% szerokości linii; ogon opisu (kości, wynik, `vs target`, modyfikator)
zawija się do drugiej linii.

```
krótka nazwa (bez zmian):        długa nazwa:
┌─ log item ──────────┐          ┌─ log item ──────────┐
│ Grimhild      12:04 │          │ Grimhild      12:04 │
│ Percepcja 45 vs 55  │          │ Odporność na dział… │
└─────────────────────┘          │ 45 vs 55 (+10)      │
                                 └─────────────────────┘
```

Kompromis: nazwa, która się mieści, nie jest obcinana wcale i wpis wygląda jak dziś — za cenę
tego, że przy bardzo długiej nazwie wynik rzutu spada do drugiej linii. Odrzucone alternatywy:
stały cap (np. `max-width: 55%`) trzyma wynik w jednej linii, ale obcina nazwę także wtedy, gdy w
linii było miejsce; etykieta zawsze jako osobny blok zmienia wygląd **wszystkich** wpisów w logu,
też krótkich.

## Ryzyka

**Baseline etykiety.** `inline-block` razem z `overflow: hidden` przenosi baseline elementu na
dolną krawędź marginesu (CSS2.1 §10.8.1 — inline-block z `overflow` innym niż `visible` ma
baseline na bottom margin edge, zamiast na baselinie ostatniej linii tekstu). Bez korekty etykieta
siedziałaby wyżej niż sąsiedni tekst w linii opisu. Dlatego `vertical-align: bottom`. Do weryfikacji
wizualnej w przeglądarce — jeśli wyjdzie o 1-2px za wysoko, drugą opcją jest `text-bottom`.

**Istniejące testy.** Kwerendy `getByText` działają dalej, bo pełny tekst zostaje w DOM. Kwerendy
po klasie `.log-list-item__character-name` też — klasa zostaje na miejscu.

Brak nowych kluczy i18n (tooltip to sama nazwa, już przetłumaczona lub wpisana przez gracza).
